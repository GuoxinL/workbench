# 01. Clarify —— 文章转载信息

> 用户原话目标：「我在网上看到其他人的文章时想要转载该文章，希望在个人工作台中的文章中添加被转载文章的人和原链接等信息，给出一个方案。」

---

## 一、背景与真实需求

个人工作台（workbench）当前文章模型只记录自有元数据（标题、标签、来源待办、发布状态），没有「转载」及其来源信息的概念。

**用户真实需求（关键）**：在浏览器里看到想转载的网页 → 通过 AI 把该网页**转换成为个人工作台的文章格式并保存**，同时自动记录被转载文章的**人（原作者）**和**原链接**等信息。即：主路径是「URL/粘贴网页 → AI 抓取正文 → 转 Markdown + 提取来源元数据 → 回填编辑器 → 用户确认授权后保存」，而非纯手工填写。

前面设计的 `repost` 等扁平字段，是 AI 自动回填的「转载来源元数据」数据契约。

## 二、范围

- 数据模型：文章新增一组转载元数据字段。
- 编辑：编辑器提供「转载信息」录入区。
- 展示：阅读视图 + 列表角标 + 公开分享署名。
- 同步：经现有 GitHub Contents API 双向同步（`kb/<id>.md` frontmatter），无需新增同步通道。

## 三、待确认问题（已与用户对齐）

| # | 问题 | 结论 |
|---|------|------|
| 1 | 下一步做到哪一步？ | 仅出方案文档，暂不实装 |
| 2 | 数据结构风格？ | 扁平字段（推荐），兼容现有解析器、不引入嵌套对象 |
| 3 | 转载信息包含哪些？ | 原作者、原链接（必填）；来源平台、原文发布时间（可选） |
| 4 | 授权如何体现？ | **删除 sourceLicense 说明字段**，改为 `sourceAuthorized` 授权闸门：未获授权即不可转载，编辑器以授权复选框为前置硬性闸门 |

## 四、不在本次范围

- 转载合规自动判定（AI 不判断是否已获授权，授权为人工确认闸门）。
- 多来源聚合 / 原作者主页聚合 / 跨文章去重。
- 方案 B 的自动抓取代理（首版可仅做「粘贴网页内容」的方案 A）。
