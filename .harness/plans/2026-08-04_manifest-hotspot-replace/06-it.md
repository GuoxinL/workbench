## 1. 验证范围与约束

本项目无团队测试环境，真实链路 = GitHub Contents API ↔ 私有数据仓库 `workbench-data`。
完整端到端 IT（IT-1~IT-4）需用户自己的细粒度 PAT（仅 `workbench-data` 仓库、Contents 读写），配置只存本机 `wb.cfg.v1`，**绝不**进入任何提交（红线 5）。

本会话可执行的两类验证：
- **A. 无令牌线上烟测**（CDP 打开线上链接）：页面挂载、无白屏/控制台报错、`SyncChip` 在 `off` 态渲染正确、产物哈希与 `dist` 一致。
- **B. 带令牌真实链路**（需用户 PAT）：IT-1~IT-4，由用户在浏览器用同步开关 + 多 profile 执行，或授权我经 CDP 注入测试用 PAT 执行。

## 3. 无令牌线上烟测（A 类，本会话执行）

- `curl -s -o /dev/null -w "%{http_code}" https://guoxinl.github.io/workbench/` 期望 `200`。
- CDP 打开 `https://guoxinl.github.io/workbench/?cb=<N>#/` 核对：
  - `document.title` 非空、应用根节点 `#app` 内有子节点（已挂载，无白屏）。
  - 无 `console.error`（白屏/脚本异常会在 console 报错）。
  - 加载的 `script[src]` 哈希与本地 `dist/assets/index-*.js` 一致（缓存破坏参数 `?cb=` 强制刷新）。
  - 未配置同步时 `SyncChip` 处于 `off` 态（纯灰点 / 灰药丸，无报错）。

> 缓存破坏：线上浏览器可能加载旧 JS，打开时带 `?cb=<递增整数>` 参数，并核对 `script[src]` hash。

## 4. 带令牌真实链路（B 类，需 PAT）

执行方式（用户任选其一）：
1. 用户自验：设置抽屉填 PAT + 数据仓库 → 按 IT-1~IT-4 操作，观察 chip 状态与数据仓库 commit。
2. 授权我经 CDP 注入**测试用** PAT（仅 `workbench-data`、最小权限）执行 IT-1~IT-4，用完在抽屉清空。
3. 换数据仓库 / 分支（如 `branch=test`）隔离真实数据（见 `test-env-deploy.md`「三种替代做法」）。
