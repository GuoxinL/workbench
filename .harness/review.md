# 代码 Review 指南

> AI 与人类 Reviewer 共同遵守的检查清单。

---

## 分类与优先级

| 严重度 | 说明 | 处理 |
|--------|------|------|
| 🔴 高（阻塞） | 安全漏洞、数据丢失风险、协议破坏、性能回归 | 必须修复才能合入 |
| 🟡 中 | 可测性差、边界漏判、错误处理缺失、命名混乱 | 需修复或明确记录 |
| 🟢 低 | 风格建议、重构空间、文档补全 | 可选 |

---

## 必查项（高严重度）

### 安全
- [ ] 所有 SQL 使用参数化查询，无字符串拼接
- [ ] 无硬编码密钥、Token、密码
- [ ] 输入校验覆盖所有外部来源（HTTP 参数、消息、文件）
- [ ] 输出按场景转义（HTML / SQL / Shell）
- [ ] 加密使用标准库

### 正确性
- [ ] 边界条件覆盖（空、单元素、超长、负数、越界）
- [ ] 并发读写共享资源有保护
- [ ] 事务边界清晰，失败回滚正确
- [ ] 对外接口遵循幂等 / 重试 / 超时约定

### 可观测性
- [ ] 关键路径有日志，包含 trace_id / request_id
- [ ] 错误路径日志包含足够上下文
- [ ] 监控指标 / 告警已配置

---

## 常规检查项（中严重度）

### 可测性
- [ ] 存在对应的 UT，覆盖率达标
- [ ] 公共接口有契约（输入/输出/异常）
- [ ] 无隐藏的全局状态

### 可维护性
- [ ] 命名清晰，避免缩写歧义
- [ ] 函数短、职责单一
- [ ] 公共代码抽取到合理层级
- [ ] 无重复代码（规则：相同逻辑出现 3 次以上必须抽象）

### 兼容性
- [ ] 协议变更向后兼容（新增字段不破坏旧客户端）
- [ ] DB schema 变更支持回滚
- [ ] 依赖版本与项目约束一致

---

## 建议项（低严重度）

- [ ] 注释说明「为什么」而非「是什么」
- [ ] 文档同步更新（`docs/apis/`、`docs/sqls/`、`docs/architecture.md`、`docs/devops/`、`docs/unittest/` 等按改动涉及的目录补）
- [ ] 测试数据逼真
