# 工作台功能验证手册（每次改动后的问题核验）

> 用途：任何代码改动（尤其是同步引擎、待办/笔记/图谱/标签、设置面板相关）合入前或部署后，
> 按本手册逐项核验，确认没有引入回归。本手册用自然语言描述「做什么、看什么、算通过」，
> 既可由人工在浏览器执行，也可由 AI 借助 `web-access` skill（CDP 驱动真实浏览器）执行。

---

## 0. 前置条件

- 代码已 `npm run build` 通过、类型检查零错误、`npm test` 全绿。
- 部署目标为 GitHub Pages，且 **Settings → Pages → Source 必须选 `GitHub Actions`**
  （若选了「Deploy from a branch」，会直接托管仓库源码，页面空白——见末尾「常见坑」）。
- 验证地址：`https://guoxinl.github.io/workbench/`。
- 若用 AI 自动验证：加载 `web-access` skill → `node .codebuddy/skills/web-access/scripts/check-deps.mjs`
  确认 CDP 已连接（浏览器需开启远程调试，如夸克 `127.0.0.1:9222`）→ 经 `localhost:3456` 代理开后台 tab 访问上述地址。

---

## 1. 加载与渲染

- **操作**：打开页面，等待加载完成。
- **看什么**：
  - 标题为「个人工作台」，不再空白。
  - 顶部出现导航与「本地模式 / 同步中 / 同步失败」状态 chip，右上角有 ⚙ 设置按钮。
- **算通过**：页面有实际内容（`#app` 内 HTML 长度 > 0），且无 JS 报错导致白屏。
- **失败信号**：整页空白、`#app` 为空、控制台报 `Failed to resolve module specifier` 或 `/src/main.ts` 404
  → 说明部署的是源码而非构建产物（见常见坑）。

---

## 2. 导航（四个视图）

- **操作**：依次点击导航「待办 / 笔记 / 图谱 / 标签」。
- **看什么**：URL hash 在 `#/todos`、`#/notes`、`#/graph`、`#/tags` 间切换，对应视图正常渲染。
- **算通过**：四个视图都能进入且互不串台。

---

## 3. 待办（Todos）

- **添加**：在「添加待办，回车创建…」输入框输入文字后 **按回车**（或点「添加」按钮），列表出现该条目。
- **编辑**：点击某条待办文字，弹出编辑对话框（标题可改，有「取消 / 保存」）。
- **完成切换**：在条目上勾选完成态；随后用过滤器验证：
  - 点「进行中」→ 已完成项不显示；
  - 点「已完成」→ 已完成项显示；
  - 点「全部待办」→ 全部显示。
- **删除**：点条目上的删除按钮（🗑），确认后从列表消失。
- **算通过**：增 / 改 / 完成态 / 过滤 / 删 全部符合预期，且刷新后（localStorage 持久化）状态保留。

---

## 4. 笔记（Notes）与双向链接

- **新建**：进入「笔记」视图，点「＋ 新建」，填写标题、标签（回车确认）、正文。
- **双链**：正文中写入 `[[其他笔记标题]]`，保存。
- **看什么**：
  - 笔记出现在左侧列表；
  - 元数据面板「出链 / 入链」计数正确（如引用了 1 个未创建链接时显示「(+1 待建) 标题（未创建）」）；
  - 当目标笔记真实存在时，两端互显「被引用 / 引用了」关系。
- **算通过**：标题、标签、正文持久化；`[[双链]]` 正确解析为链接并计入出/入链。

---

## 5. 图谱（Graph）

- **操作**：进入「图谱」视图。
- **看什么**：渲染出 SVG 画布，含「重新布局 / 滚轮缩放 / 拖拽节点」控件。
- **算通过**：存在 SVG 节点容器；当笔记间存在真实双向链接时，显示出节点与连线；
  无链接时给出「还没有笔记之间的引用关系」空态提示（属正常）。
- **失败信号**：视图空白、控件缺失、或笔记已互联却无任何节点 → 图谱渲染异常。

---

## 6. 标签云（Tags）

- **操作**：进入「标签」视图。
- **看什么**：以标签云形式列出所有标签及引用计数（如 `ci 1`）。
- **算通过**：新建笔记时打的标签在此出现并带正确计数。

---

## 7. 设置 → GitHub 同步（关键回归区）

- **操作**：点 ⚙ 打开设置，切到「GitHub 同步」区段。
- **字段**：启用同步开关、仓库 `owner/repo`、分支、Personal Access Token、轮询间隔、API 代理基址。
  （令牌仅存 localStorage，绝不落库、不打印日志——核验时也不要把令牌回显到对话。）
- **测试连接（最重要）**：
  - **当配置不完整**（例如「API 代理基址」为空，或仓库/分支/令牌任一缺失）时，
    点「测试连接」应 **返回「配置不完整：请填写 owner/repo（格式 owner/repo）、分支与令牌」**，
    **不得**发起 `GET /repos/` 请求、不得出现 404、不得把状态置为「同步失败」。
  - **当配置完整**时，点「测试连接」应发起真实连通性校验并给出成功/失败明细。
- **五步诊断 / 导出备份**：按钮可点开，分别给出分步诊断信息与本地备份导出。
- **算通过**：不完整配置下测试连接友好提示且不误报；完整配置下能真正联通。

> ⚠️ **回归红线**：任何改动都不能让「配置不完整」走到网络请求 / 404 / 「同步失败」。
> 对应代码校验在 `src/services/github/diagnose.ts` 的 `isConfigComplete()` 与 `testConnection()`，
> 以及 `src/services/sync/engine.ts` 的 `doSync()` 守卫。改动这两个文件后务必重跑本项。

---

## 8. 同步状态 chip

- **看什么**：未配置或配置不完整时显示「本地模式」；配置完整且在同步中显示「同步中」；
  真正出错才显示「同步失败」。
- **算通过**：默认全新浏览器（无 token）进入即为「本地模式」，绝不直接「同步失败」。

---

## 9. 通过 / 不通过判定

- **通过**：第 1–8 项全部符合「算通过」描述，且控制台无未捕获错误。
- **不通过**：任一关键项不符（尤其第 1 项白屏、第 7 项测试连接 404、第 8 项误报同步失败）
  → 阻断合入，回到对应模块排查。

---

## 附：常见坑

1. **页面空白、`/src/main.ts` 404**：GitHub Pages 的 Source 被设成「Deploy from a branch」。
   改回 `GitHub Actions`，再于 Actions 重跑 `Deploy` 工作流即可（部署产物是 `dist/`，
   含 `./assets/index-*.js`，相对路径适配 `/workbench/` 子路径）。
2. **测试连接 404 / 误报同步失败**：配置不完整时同步引擎仍发了请求。检查
   `isConfigComplete()` 守卫是否在所有入口（测试连接、doSync）生效。
3. **双链不计数**：确认笔记正文用 `[[标题]]` 语法，且目标笔记标题完全一致（含空格）。
4. **验证前清场**：自动化验证会在浏览器 localStorage 留下测试数据（待办/笔记/标签），
   验证结束后记得在对应视图删除，避免污染真实数据。
