## 范围

**只收录本项目私有的、非公知的术语。** 行业通用概念（localStorage、PWA、CORS、Markdown、Base64、Wiki 链接、乐观锁、防抖、IIFE、力导向布局 等）和编程语言标准术语**不在本表范围**——AI 和工程师都已经知道这些。

本表的价值在于：一个熟练的高级工程师首次接触本项目时，哪些词他**无法靠经验推断**其含义，或者**会按通用含义理解从而误读代码**。

## 使用规则

- 代码/文档中首次使用本表中的术语时，用全称或括号注明缩写含义
- 新创缩写必须先在本表注册，禁止在代码中直接使用未登记的私有缩写
- 发现同义词混用时，在「易混术语对照」段统一约定，后续只用一种
- AI 遇到不认识的项目特有词汇时，应主动查阅本表或追问

| **`slug()`** | — | — | ⚠️ **不是**通常意义的 URL slug（不转拼音、不转连字符、不去标点）。本项目的 `slug()` 只做三件事：`trim` + 转小写 + 把连续空白折叠成单个空格。它是**双链标题匹配与笔记查重的唯一键**，因此「My Note」「my  note」被视为同一篇。按 URL slug 理解会得出完全错误的匹配结论 | `js/util.js:119-121`；消费方 `js/store.js:200-203`、`js/notes.js:82,89`、`js/markdown.js:19,35` |

## 易混术语对照

| 术语 A | 术语 B | 区别 | 本项目统一用 |
|--------|--------|------|-------------|
| **待办**（实体 Todo） | **待办**（状态 `status='todo'`） | 同一个中文词指两样东西：前者是数据实体（`data.todos[]` 里的一条记录），后者是该实体三档状态之一（`todo`/`doing`/`done` → 待办/进行中/已完成）。`STATUS_TEXT` 里的「待办」是**状态**（`js/store.js:28`） | 指实体写「待办卡片」，指状态写「待办态」或直接用 `status='todo'` |
| **引用了**（`outMap`） | **被引用**（`inMap`） | UI 名 ↔ 代码名不一致：笔记详情右侧「↗ 引用了」= `outMap[id]`（本篇正文里出现的 `[[X]]` 所指向的笔记）；「↙ 被引用」= `inMap[id]`（其它笔记正文里引用了本篇，带上下文摘录 `ctx`）。**第三个易漏的量是 `missing`**——本篇引用了但目标笔记尚不存在，UI 计在「引用了」的 `(+N 待建)` 里，**不计入 `outMap` 长度** | 代码用 `outMap`/`inMap`/`missing`，UI 文案用「引用了」/「被引用」/「待建」 |
| **路径白名单**（`ALLOW`） | **来源白名单**（`ALLOW_ORIGINS`） | 都在 Worker 里、都返回 403，但一个管"转发到 GitHub 的哪些接口"（正则匹配 `url.pathname`），一个管"哪个站点能调用本 Worker"（匹配请求的 `Origin` 头）。新增一个 GitHub 接口要改前者，换部署域名要改后者，改错方向排查会绕远 | 必须带前缀说「路径白名单」/「来源白名单」，禁止只说「白名单」 |
| **同步内部态 `ok`** | **UI「已同步」** | **不是一一对应**：内部状态机只有 `idle`/`syncing`/`ok`/`error`/`off` 五态，但 `ok` 态下 UI 会再看一眼 `S.dirty`——脏则显示「待同步」，不脏才显示「已同步 <相对时间>」。所以顶栏出现「待同步」时状态机其实是 `ok`，**不是错误** | 谈状态机用 `ok`/`error`/`off`，谈界面用「已同步」/「待同步」/「同步失败」/「本地模式」 |
| **色号**（`color:'amber'`） | **颜色展示名**（「橙 · 重要」） | 数据里只存色号；`COLORS[].name` 是「色名 · 语义」合成串。UI 两处用法还不同：色块 hover 提示用**全称**「橙 · 重要」，卡片底部标签只取 `split(' · ')[1]` 的**语义半段**「重要」 | 代码里一律用色号；文档描述分类时写「橙 · 重要」全称 |
| **`todo.noteId`** | **`note.fromTodo`** | 待办转笔记时同时写下的**一对反向指针**，方向相反：`noteId` 是待办 → 笔记，`fromTodo` 是笔记 → 待办。删除笔记时只清空 `noteId`（`js/store.js:228-230`），`fromTodo` 会指向一个已成墓碑的待办，读取时须判空 | 按方向直呼字段名，勿统称「关联 id」 |
| **代码仓库 `workbench`** | **数据仓库 `workbench-data`** | 两个不同的 GitHub 仓库：前者放源码、**必须公开**（GitHub Pages 要求）；后者只放 `data/workbench.json`、**必须私有**（存的是个人待办与笔记）。同步指向的永远是后者 | 明确写「代码仓库」/「数据仓库」，禁止只说「仓库」 |
| **`WB.notes.flush()`** | **`debounce().flushNow()`** | 前者是笔记模块对外暴露的「立刻把编辑器内容落盘」入口，实现上就是调后者；后者是 `util.debounce` 通用包装器上的方法，**无条件立即执行**（不检查是否有 pending） | 跨模块调用（`app.js` 同步前/离场前）用 `WB.notes.flush()` |

## 不收录清单（提醒）

以下类型的术语**不要**添加到本表：

- 行业标准：API、SDK、REST、CI/CD、CORS、PWA、Base64、Markdown、Wiki 链接...
- 语言/浏览器标准：localStorage、Promise、`AbortController`、`fetch`、IIFE、防抖（debounce）...
- 通用分布式/存储概念：乐观锁、CAS、最终一致性、软删除、tombstone 的通用定义...
- 通用设计模式：MVC、单例、观察者、事件总线...
- **公开文档定义的第三方概念**：GitHub Contents API 的 `sha` 字段语义、PAT / 细粒度令牌、GitHub Pages、Cloudflare Worker、`.nojekyll`...
- **名字自解释的标识符**：`apiBase`（API 根地址）、`poll`（轮询间隔）、`autoSave`、`livePreview`、`renderList`...
- 任何一个高级工程师不用查就能理解的词
- 任何搜索引擎搜一下就能找到准确定义的词
